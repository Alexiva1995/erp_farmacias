Módulo "Por Pagar" - Corrección de Problemas Técnicos

✅ Completado 📅 Fecha: 2025-09-10

📋 Resumen del Problema

El módulo "Por Pagar" presentaba múltiples problemas técnicos que impedían su funcionamiento correcto, desde la carga inicial de datos hasta el procesamiento de pagos y conversión de monedas.

⚠️ Síntomas Observados - Fase 1 (Carga de Datos)

  • Tabla de pagos pendientes completamente vacía
  • Errores en consola: "Error al cargar pagos pendientes: undefined"
  • Errores en consola: "No se pudieron cargar los proveedores"
  • Respuestas HTML en lugar de JSON desde la API

⚠️ Síntomas Observados - Fase 2 (Procesamiento de Pagos)

  • Modal de procesamiento mostraba "N/A" en todos los campos de conversión
  • Error RangeError: Invalid currency code: Bs al formatear monedas
  • Error 405 Method Not Allowed al procesar pagos
  • Error 400 Bad Request por validación de duplicados incorrecta
  • Facturas no se marcaban como pagadas correctamente
  • Notificaciones de error cuando el pago era exitoso

🔍 Diagnóstico del Problema

❌ Problemas Identificados

  • Rutas API Incorrectas: Frontend llamaba a rutas inexistentes
  • Configuración CORS: Solo permitía dominios específicos
  • Autenticación Incorrecta: Buscaba tokens que no existían
  • Campos de BD Incorrectos: Usaba campos de fecha erróneos

✅ Soluciones Implementadas

  • Rutas Corregidas: Alineadas con backend
  • CORS Actualizado: Agregados dominios locales
  • Autenticación por Sesión: Configurada correctamente
  • Campos de BD: Corregidos para usar payment_date

✅ Problema Resuelto: Autenticación por Sesión

🎯 Diagnóstico del Problema de Autenticación

El sistema está configurado para usar Laravel Sanctum con autenticación por sesión. El problema era que el interceptor de axios estaba buscando un token accessToken que no existe en este tipo de autenticación.

Configuración actual del sistema:

  • Backend: Laravel Sanctum con auth:sanctum middleware
  • Autenticación: Por sesión (cookies), no por token
  • Frontend: Corregido para usar autenticación por sesión
  • Estructura de usuarios: Campo is_active en lugar de is_admin

🔧 Solución Implementada

✅ Autenticación por sesión implementada correctamente:

// Interceptor corregido para usar autenticación por sesión axiosInstance.interceptors.request.use( (config) => { // No necesitamos agregar Authorization header // Laravel Sanctum maneja la autenticación via cookies de sesión return config }, (error) => { return Promise.reject(error) } )

Configuración adicional:

  • Sanctum stateful domains: Agregado localhost:5173 y 127.0.0.1:5173
  • CORS: Configurado para múltiples dominios locales
  • Middleware: EnsureFrontendRequestsAreStateful ya configurado
