1. 📊 Resumen Ejecutivo

🎯 Objetivo del Módulo

El módulo de Prestaciones Sociales es un sistema integral para la gestión de beneficios laborales en el ERP farmacéutico, incluyendo el cálculo automático de liquidaciones, pagos individuales y el manejo de deducciones.

📈 Funcionalidades Principales

  • Liquidación de Empleados: Cálculo automático de prestaciones sociales al despedir empleados
  • Pagos Individuales: Gestión de vacaciones, bono vacacional y utilidades
  • Cálculo de Salario Promedio: Nuevo sistema basado en los últimos 6 salarios en Bolívares
  • Validación de Pagos Anuales: Prevención de pagos duplicados en el mismo año
  • Integración Contable: Registro automático de transacciones y gastos
  • Compatibilidad Cross-Platform: Funciona en Windows y Linux
✅ Estado Actual: Módulo completamente operativo con todas las funcionalidades implementadas y probadas.

2. 🆕 Nuevas Funcionalidades v2.3

🔄 Generación Automática de Payslip Details

📋 Descripción

Implementación de generación automática de payslip_details cuando se realizan pagos individuales, eliminando la necesidad de ejecutar comandos manuales después de cada pago.

🔧 Problema Resuelto

Problema: Los pagos individuales se registraban en users_salary_details pero no generaban automáticamente los payslip_details correspondientes, causando que las deducciones no aparecieran en el modal de despido.
Solución: Implementado método generatePayslipDetailForPayment() que se ejecuta automáticamente en cada pago individual.

⚙️ Implementación Técnica

private function generatePayslipDetailForPayment($salaryDetail, $amount): void { try { // Buscar o crear un payslip para la fecha actual $payslip = Payslip::firstOrCreate( [ 'payslip_date' => Carbon::now()->format('Y-m-d'), 'name' => 'Pago Individual - ' . Carbon::now()->format('Y-m-d'), ], [ 'payslip_date' => Carbon::now()->format('Y-m-d'), 'name' => 'Pago Individual - ' . Carbon::now()->format('Y-m-d'), 'total' => 0, 'status' => 1, ] ); // Crear el payslip_detail PayslipDetails::create([ 'payslip_id' => $payslip->id, 'users_salary_details_id' => $salaryDetail->id, 'amount' => $amount, ]); // Actualizar el total del payslip $totalAmount = PayslipDetails::where('payslip_id', $payslip->id)->sum('amount'); $payslip->update(['total' => $totalAmount]); } catch (\Exception $e) { Log::error('Repository', [ 'message' => 'Error generando payslip detail automáticamente', 'error' => $e->getMessage(), 'salary_detail_id' => $salaryDetail->id ]); } }

✅ Beneficios

  • Automático: No requiere intervención manual
  • Inmediato: Las deducciones aparecen al instante
  • Confiable: Manejo de errores incluido
  • Consistente: Todos los pagos se procesan igual

📅 Corrección de Cálculo de Años Activos

📋 Descripción

Corrección del cálculo de años activos en el método getSettlementData() para usar únicamente Carbon en lugar de consultas SQL que podían fallar.

🔧 Problema Resuelto

Problema: El método getSettlementData() sobrescribía el cálculo correcto de Carbon con un valor SQL que fallaba, causando que empleados con más de 1 año de antigüedad mostraran 0 días en prestaciones.
Solución: Eliminada la línea que sobrescribía $activeYears con el valor SQL, usando únicamente el cálculo de Carbon.

⚙️ Cambio Técnico

// ANTES (problemático): $activeYears = (int) $settlement?->active_years ?? 1; // DESPUÉS (corregido): // Usar el cálculo de Carbon en lugar del SQL que puede fallar // $activeYears = (int) $settlement?->active_years ?? 1;

💰 Cálculo de Salario Promedio

📋 Descripción

Implementación de un nuevo sistema de cálculo de salario promedio basado en los últimos 6 salarios quincenales del empleado, convertidos a Bolívares usando la tasa de cambio del día de pago.

🔢 Fórmula de Cálculo

Salario Promedio Mensual = (Suma de Salarios en Bs. ÷ Cantidad de Salarios) × 2

📊 Ejemplo Práctico

Empleado: Alexis Valera
Últimos 3 salarios: 6,000 Bs. cada uno
Cálculo: (18,000 ÷ 3) × 2 = 12,000 Bs.
Resultado: Salario promedio mensual de 12,000 Bs.

📋 Descripción

Implementación del cálculo de salario integral para prestaciones sociales según la fórmula establecida por el jefe.

🔢 Fórmula de Salario Integral

Salario Integral = Salario Diario + [(30 × Salario Diario) ÷ 360] + [(15 × Salario Diario) ÷ 360]

⚙️ Implementación Técnica

🔧 Corrección de Fórmulas de Prestaciones Sociales

📋 Descripción

Implementación de correcciones fundamentales en las fórmulas de cálculo de prestaciones sociales según especificaciones del jefe, permitiendo prestaciones fraccionadas y nuevas reglas de bonificación.

🔧 Problema Resuelto

Problema: Las fórmulas anteriores bloqueaban completamente las prestaciones para empleados con menos de 1 año de antigüedad, y las fórmulas de cálculo no seguían las reglas de negocio correctas.
Solución: Eliminada la regla de negocio fundamental restrictiva e implementadas nuevas fórmulas con prestaciones fraccionadas y bonificaciones por años completados.

⚙️ Nuevas Fórmulas Implementadas

🏢 Prestaciones Sociales
REGLA ESPECIAL:
Si meses < 6: días = meses × 5
Si meses ≥ 6: días = 30
Bonificación: +2 días por cada año completo adicional (a partir del 2do año)
🏖️ Vacaciones
FÓRMULA BASE: días = round(15 × años) (redondeado a entero)
Bonificación: +1 día por cada año completo adicional (a partir del 2do año)
🎁 Bono Vacacional
IGUAL QUE VACACIONES
Fórmula: días = round(15 × años) + bonificaciones
💰 Utilidades
FÓRMULA SIMPLE: días = round(30 × años) (redondeado a entero)
Sin bonificaciones adicionales

📊 Ejemplos Prácticos

Empleado con 6 meses:
- Prestaciones Sociales: 30 días (regla especial)
- Vacaciones: 8 días (round(15 × 0.5))
- Bono Vacacional: 8 días
- Utilidades: 15 días (round(30 × 0.5))
Total: 61 días
Empleado con 2 años:
- Prestaciones Sociales: 32 días (30 + 2 bonificación)
- Vacaciones: 31 días (30 + 1 bonificación)
- Bono Vacacional: 31 días
- Utilidades: 60 días
Total: 154 días

✅ Beneficios

  • Prestaciones Fraccionadas: Los empleados con menos de 1 año ahora tienen derecho a prestaciones
  • Fórmulas Simplificadas: Eliminadas fórmulas complejas con restas problemáticas
  • Bonificaciones Claras: Sistema transparente de bonificaciones por años completados
  • Reglas Especiales: Prestaciones sociales con regla especial para menos de 6 meses
  • Consistencia: Todas las fórmulas siguen la misma lógica base
  • Días Enteros: Todos los días se muestran como números enteros para mejor legibilidad

💸 Deducciones Automáticas

📋 Descripción

Sistema de deducciones automáticas que se generan cuando se crean las prestaciones sociales, eliminando la necesidad del botón manual de pago.

🔄 Proceso Automático

  1. Generación de Prestación: Se crea automáticamente según reglas de negocio
  2. Registro en Base de Datos: Se crea registro en users_salary_details
  3. Vinculación con Nómina: Se genera automáticamente payslip_details
  4. Actualización de Totales: Se actualiza el total del payslip
  5. Aparición en Liquidación: Las deducciones aparecen automáticamente en el modal de despido

🔍 getEmployeeLastSalariesInBs()

public function getEmployeeLastSalariesInBs(Employee $employee, int $count = 6): array { $salaries = DB::table('employees') ->select([ 'pd.amount as amount_bs', 'ps.payslip_date', 'er.rate as exchange_rate', DB::raw("pd.amount * er.rate AS amount_bs_calculated") ]) ->leftJoin('users as u', 'u.id', '=', 'employees.user_id') ->leftJoin('users_salary_details as usd', 'usd.user_id', '=', 'u.id') ->leftJoin('payslip_details as pd', 'pd.users_salary_details_id', '=', 'usd.id') ->leftJoin('payslips as ps', 'ps.id', '=', 'pd.payslip_id') ->leftJoin('salary_concepts as sc', 'sc.id', '=', 'usd.salary_concept_id') ->leftJoin('exchange_rates as er', function($join) { $join->on(DB::raw("DATE_FORMAT(er.created_at, '%Y-%m-%d')"), '=', DB::raw("DATE_FORMAT(ps.payslip_date, '%Y-%m-%d')")) ->where('er.currency_code', '=', 'USD'); }) ->where('employees.id', $employee->id) ->where('sc.name', 'Salario Base') ->whereNotNull('pd.amount') ->whereNotNull('er.rate') ->orderByDesc('ps.payslip_date') ->limit($count) ->get(); return $salaries->map(function($salary) { return [ 'amount_bs' => round($salary->amount_bs_calculated, 2), 'payslip_date' => $salary->payslip_date, 'exchange_rate' => $salary->exchange_rate ]; })->toArray(); }

🧮 calculateAverageSalaryForBenefits()

public function calculateAverageSalaryForBenefits(Employee $employee): array { $lastSalaries = $this->getEmployeeLastSalariesInBs($employee, 6); if (empty($lastSalaries)) { return [ 'average_salary' => 0, 'salaries_count' => 0, 'last_salaries' => [], 'calculation_details' => 'No se encontraron salarios registrados' ]; } $salariesCount = count($lastSalaries); $totalAmount = array_sum(array_column($lastSalaries, 'amount_bs')); $averageQuincenal = $totalAmount / $salariesCount; $averageMonthly = $averageQuincenal * 2; // Convertir de quincenal a mensual return [ 'average_salary' => round($averageMonthly, 2), 'salaries_count' => $salariesCount, 'last_salaries' => $lastSalaries, 'calculation_details' => "Promedio de {$salariesCount} salarios: " . number_format($totalAmount, 2) . " Bs. ÷ {$salariesCount} = " . number_format($averageQuincenal, 2) . " Bs. × 2 = " . number_format($averageMonthly, 2) . " Bs." ]; }

10. 🔧 Solución de Problemas

❌ Problemas Resueltos

🚫 Eliminación de Botón Manual de Pago

Problema: El jefe solicitó eliminar el botón de pago manual de prestaciones sociales para evitar pagos duplicados y errores humanos.
Causa: El botón manual permitía pagos duplicados y no seguía las reglas de negocio automáticas.
Solución: Eliminado completamente el botón de pago manual y implementado sistema de generación automática con deducciones automáticas.

💸 Deducciones Automáticas

Problema: Al eliminar el botón manual, las deducciones no aparecían en las liquidaciones porque no se generaban automáticamente.
Causa: Las prestaciones se generaban pero no se vinculaban correctamente con payslip_details para aparecer como deducciones.
Solución: Implementado sistema completo de deducciones automáticas que se generan cuando se crean las prestaciones sociales.

🔄 Deducciones No Aparecían en Modal de Despido

Problema: Los pagos individuales se registraban correctamente pero no aparecían como deducciones en el modal de despido.
Causa: Faltaban los payslip_details correspondientes a los pagos individuales.
Solución: Implementada generación automática de payslip_details en el método payment().

📅 Empleados de Prueba con 0 Días en Prestaciones

Problema: Los empleados de prueba mostraban 0 días en todas las prestaciones sociales.
Causa: Se creaban con fecha actual, teniendo menos de 1 año de antigüedad.
Solución: Implementado sistema para actualizar fechas de creación a 2 años atrás.

🧮 Cálculo Incorrecto de Años Activos

Problema: Empleados con más de 1 año de antigüedad mostraban 0 días en prestaciones.
Causa: El método getSettlementData() sobrescribía el cálculo correcto de Carbon con un valor SQL que fallaba.
Solución: Eliminada la línea problemática, usando únicamente el cálculo de Carbon.

🐛 Montos Negativos

Problema: Los cálculos de liquidación generaban montos negativos.
Solución: Implementado max(0, round($totalSettlementUsd - $totalDeductionsUsd, 2))

📅 Fecha de Inicio Incorrecta

Problema: La fecha de inicio se mostraba incorrectamente.
Solución: Reemplazado MySQL CURDATE() con Carbon::now()

📝 Errores en Logs

Problema: Errores de sintaxis en los logs.
Solución: Corregido Log::info('Repository', ['sub-query' => $sub])

🚪 No se Podía Despedir Empleados

Problema: Auth::user() retornaba null en comandos de consola.
Solución: Implementado Auth::user()?->id ?? 1

🖥️ Compatibilidad Windows/Linux

Problema: Funciones MySQL específicas no funcionaban en Windows.
Solución: Reemplazadas con alternativas de Carbon y DATE_FORMAT

🔄 Pagos Duplicados

Problema: Se permitían pagos duplicados en el mismo año.
Solución: Implementada validación anual con hasPaidThisYear()

⚠️ Problemas Comunes

💾 Sin Salarios Registrados

Síntoma: "Al empleado no se le han asignado salarios"
Causa: No hay registros en payslip_details
Solución: Generar nóminas para el empleado

🔄 Deducciones No Aparecen Después de Pago Individual

Síntoma: Se realiza un pago individual pero no aparece como deducción en el modal de despido
Causa: El pago se registró en users_salary_details pero no se generó el payslip_detail correspondiente
Solución: Ejecutar php artisan app:generate-payslip o usar la nueva funcionalidad automática

📅 Empleados de Prueba con 0 Días

Síntoma: Empleados de prueba muestran 0 días en todas las prestaciones
Causa: Fecha de creación es actual, tienen menos de 1 año de antigüedad
Solución: Actualizar fecha de creación a 2 años atrás usando herramientas de gestión de empleados de prueba

💱 Sin Tasa de Cambio

Síntoma: Deducciones no aparecen
Causa: No hay tasa de cambio para la fecha de pago
Solución: Ejecutar php artisan app:update-exchange-rate

🔍 Error 500 en API

Síntoma: Error 500 al cargar empleados
Causa: Problema con GROUP BY en consulta SQL
Solución: Verificar que users.id esté en GROUP BY
