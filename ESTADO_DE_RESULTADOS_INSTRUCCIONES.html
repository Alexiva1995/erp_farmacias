📊 Estado de Resultados - Instrucciones de Implementación

🎯 1. TAREA DE ESTADO DE RESULTADOS

📋 Descripción de la Tarea

Implementar un Estado de Resultados para el ERP de farmacias que permita visualizar de manera clara y organizada la información financiera de la empresa, incluyendo ingresos, costos, gastos operativos y utilidad neta.

🏗️ Estructura Requerida

El Estado de Resultados debe incluir 4 secciones principales organizadas en cuadritos:

Sección Descripción Fuente de Datos
1. Ingresos Ventas totales de órdenes completadas Tabla orders con status = 'Completed'
2. Costos Costo de medicamentos vendidos Tabla order_details (unit_cost × quantity)
3. Gastos Operativos Salarios, servicios, alquiler, etc. Tabla expenses agrupados por categorías
4. Utilidad Neta Ingresos - Costos - Gastos Cálculo automático

🔍 Funcionalidades de Filtrado

  • Filtros de Fecha: Rango personalizable desde el inicio de los tiempos
  • Filtros Rápidos:
    • Últimos 15 días
    • Últimos 30 días
    • Últimos 60 días
    • Últimos 90 días
    • Mes en curso
    • Mes anterior

📊 Tabla Dinámica

Debe incluir una tabla que liste todas las transacciones por fecha:

  • Todas las ventas con sus costos correspondientes
  • Todos los gastos operativos organizados por categoría
  • Vista filtrable según el rango de fechas seleccionado
⚠️ Nota Importante: Debes consultar con Joss Lady sobre cómo obtener el costo de los productos de las órdenes, aunque según el análisis, los costos ya se almacenan en order_details.unit_cost.

🏗️ Estructura Detallada de Tablas

📋 Tabla: orders
CREATE TABLE orders ( id BIGINT PRIMARY KEY, client_id BIGINT (FK → clients), seller_id BIGINT (FK → users), cash_closing_id BIGINT (FK → cash_closing), total_amount DECIMAL(12,2), -- INGRESOS TOTALES total_amount_usd DECIMAL(12,2), -- INGRESOS EN USD money_returns DECIMAL(12,2), currency ENUM('Bs', 'USD', 'COP'), -- MONEDA DE LA ORDEN order_date DATETIME, -- FECHA DE LA ORDEN status ENUM('Completed', 'Cancelled', 'Abandoned', 'Pending', 'closed', 'Reserved'), has_multiple_currencies BOOLEAN, payment_methods JSON, -- MÉTODOS DE PAGO created_at TIMESTAMP, updated_at TIMESTAMP );
📋 Tabla: order_details
CREATE TABLE order_details ( id BIGINT PRIMARY KEY, order_id BIGINT (FK → orders), pack_id BIGINT (FK → product_packs), product_type ENUM('normal', 'offer', 'pack'), product_id BIGINT (FK → products), quantity INTEGER, -- CANTIDAD VENDIDA price DECIMAL(12,2), -- PRECIO TOTAL DEL ITEM unit_cost DECIMAL(12,2), -- COSTO UNITARIO ⭐ CLAVE PARA COSTOS unit_price_usd DECIMAL(12,2), -- PRECIO UNITARIO EN USD created_at TIMESTAMP, updated_at TIMESTAMP );
📋 Tabla: expenses
CREATE TABLE expenses ( id BIGINT PRIMARY KEY, name VARCHAR(255), -- NOMBRE DEL GASTO category_id BIGINT (FK → expense_categories), amount DECIMAL(15,2), -- MONTO EN MONEDA ORIGINAL amount_usd DECIMAL(15,2), -- MONTO EN USD ⭐ CLAVE PARA GASTOS currency VARCHAR(10), -- MONEDA DEL GASTO has_invoice BOOLEAN, is_deductible BOOLEAN, expense_date DATE, -- FECHA DEL GASTO user_id BIGINT (FK → users), created_at TIMESTAMP, updated_at TIMESTAMP );
📋 Tabla: expense_categories
CREATE TABLE expense_categories ( id BIGINT PRIMARY KEY, name VARCHAR(255) UNIQUE, -- NOMBRE DE LA CATEGORÍA created_at TIMESTAMP, updated_at TIMESTAMP );

🔄 Estados de Órdenes

Las órdenes pueden tener los siguientes estados:

  • Completed - ✅ Para ingresos
  • Pending - ⏳ En proceso
  • Cancelled - ❌ Cancelada
  • Abandoned - 🚫 Abandonada
  • Reserved - 📋 Reservada
  • closed - 🔒 Cerrada

💱 Sistema de Monedas

El sistema maneja múltiples monedas:

  • USD - Dólares estadounidenses
  • BS - Bolívares venezolanos
  • COP - Pesos colombianos

Todas las conversiones se manejan automáticamente y se almacenan en USD para cálculos unificados.

🎯 Cálculos Específicos Requeridos

💰 Ingresos

// Total de ingresos en USD SELECT SUM(COALESCE(total_amount_usd, total_amount)) as total_income FROM orders WHERE status = 'Completed' AND order_date BETWEEN ? AND ?

💸 Costos

// Total de costos en USD SELECT SUM(od.unit_cost * od.quantity) as total_costs FROM order_details od JOIN orders o ON o.id = od.order_id WHERE o.status = 'Completed' AND o.order_date BETWEEN ? AND ?

📊 Gastos Operativos

// Gastos por categoría SELECT ec.name as category_name, SUM(e.amount_usd) as total_amount FROM expenses e JOIN expense_categories ec ON ec.id = e.category_id WHERE e.expense_date BETWEEN ? AND ? GROUP BY ec.id, ec.name ORDER BY total_amount DESC

📈 Utilidad Neta

// Cálculo de utilidad neta $netProfit = $totalIncome - $totalCosts - $totalExpenses;

⚠️ Consideraciones Importantes

Fechas: Usar el campo order_date para órdenes y expense_date para gastos.
Estados: Solo considerar órdenes con status = 'Completed' para ingresos y costos.
